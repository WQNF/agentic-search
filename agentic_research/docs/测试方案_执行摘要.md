# 测试方案执行摘要（给项目负责人）

## 一句话

旧套件的“100% 成功”是**关键词匹配 + 估算 token + 分母错误**堆出来的，不能用于验收。
v2 把 21 项指标拆成“工作流层 / 数据层 / 报告层”，用**同期官方真值 + 语义成功 + 真实 token + 置信区间**重算；
工装已放在 `backend/tests/eval/`，一条命令可复跑。

## 旧结果不能用的 5 个硬证据

1. **成功判定**：`check_core_sections` 只做 `"公司概览" in report_md` + 尾部 >10 字符；
   14/30 份 `final_status=partial_success`、TSLA `metric_count=0`，仍被判“成功”。
2. **150 字段从未测**：`TOTAL_150_FIELDS` 是约 83 个字段**名**；实际只比较 5 只股票 × 25 键 = 125 个值；
   `None==None` 还判对。
3. **CN/HK 0% 是键名没对上**：系统输出中文扁平字典，真值是英文键；不是数据错。
4. **工具成功率上限 50%**：`tool_call` 与 `tool_success` 被同时计数；SEC/akshare/yfinance 调用根本没打日志。
5. **成本是估算**：`report_len*1.5` + 硬编码单价；结果文件里每条 `estimated_cost_rmb=0.0`。

## v2 改了什么

| 维度 | 旧 | 新 |
|---|---|---|
| 成功 | section 关键词 + 不崩 | 标题结构 + 实义内容 + fatal 定义 |
| 字段 | 83 个键名 × 5 只 | 30 家 × 5 字段 = 150，报告层解析 |
| 真值 | 圆整、无期间、无来源 | 同期官方/独立源，记录 `period_end/source/tier` |
| 工具 | 日志事件计数 | 函数边界 + 语义成功 + provider |
| 成本 | 估算 | LangChain callback 真实 token × 单价 |
| 故障 | `final_status!=pending` 即成功 | 每类故障 5 条契约 |
| 统计 | 点估计 | Wilson 95% CI + bootstrap + McNemar |
| 人工 | 无 | 10 份 × 2 人 × 4 维 rubric |
| 错误 | 无 | 10 类 taxonomy + Top3 |

## 150 字段是什么

30 家 × 5 个字段：

- `revenue` 营业收入
- `net_income` 归母净利润
- `gross_margin` 毛利率
- `net_margin` 净利率
- `operating_margin` 营业利润率

选这 5 个的原因：报告 prompt 要求/报告实际披露、三地都能从标准报表得到、不依赖当日股价。
不把 ROE 放进 150：官方 ROE 有加权/期末/年化多种口径，1% 容差下无法唯一判定；ROE 当前只作为可选诊断字段，不计入 21 项。

## 必须提前确认的 4 件事

1. **真值来源**：US 已用 SEC XBRL（official）；CN/HK 当前是 vendor（新浪/东财），
   最终交付前需对 20% 字段用交易所年报 PDF 复核，把 `verified` 改 `True`。
   未复核时请在表内标“参考值口径”，不要写成“与官方一致”。
2. **provider**：当前 `.env` 是 `SEARCH_PROVIDER=serper`、`STOCK_QUOTE_PROVIDER=eastmoney`，
   所以 Tavily / yfinance / Finnhub 是 **N/A**，不是 0%。表内已按 N/A 输出，另报 serper/eastmoney。
3. **单价**：`results/prices.json` 目前是空的（`null`）。运行日从 DeepSeek 账单填
   `input_per_1m / output_per_1m / cached_input_per_1m`，否则成本列只能写“待单价”。
4. **人工评分**：17–20 必须 2 人独立盲评；工装只能给 N/A，不能代替人。

## 这套工装会顺带暴露的 6 个产品问题

1. `CNAdapter` 对任意 6 位代码返回 Entity → `999999.SH` 被“解析成功”。
2. CN/HK 公司概况不支持 → `profile_status=partial` 必然发生。
3. CN/HK 行情 provider=eastmoney 的 secid 构造只支持美股 → 行情必失败。
4. 港股财务只有利润表，没有资产负债表 → ROE/资产负债率类字段不可得。
5. 港股 `get_hk_financial_abstract` 用 `FISCAL_YEAR`（值是 `"12-31"`）取最新期 → 取到错误年份。
6. `05_report.md` 被 `json.dump` 成转义字符串 → API/下载返回的不是 Markdown，前端渲染会变成一行。

这些不是测试口径能修的；建议在评测报告里单列“待修复项”，不要混进模型能力评价。

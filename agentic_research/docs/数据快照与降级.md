# 数据快照与降级（解决 akshare / 外部接口不稳定）

> 适用：`agentic_research/backend`
> 代码：`app/services/snapshot_store.py`
> 脚本：`scripts/prewarm_data.py`、`scripts/seed_snapshots_from_eval.py`

## 1. 问题

`akshare` 的 A 股/港股接口经常出现：

- 限流、连接被重置、代理断开（`ProxyError` / `RemoteDisconnected`）；
- 返回空表或字段缺失；
- 不同接口的“最新期”口径不一致。

如果每次报告都实时打这些接口，就会出现“同一家公司今天能跑、明天跑不出来”，
评测也无法复现。

## 2. 方案：快照优先 + 实时回退

```
请求财务/概况
   │
   ├─ 本地快照存在且未过期？ ── 是 → 直接用（source=snapshot, stale=False）
   │
   └─ 否 → 实时抓取
            ├─ 成功 → 原子写快照 → 返回（source=live, stale=False）
            └─ 失败 → 读旧快照 → 返回（source=snapshot, stale=True）
                        └─ 没有旧快照 → 抛错，走现有降级
```

- **财务/概况：快照优先**。30 天内直接读本地，不再打 akshare；
  过期才实时刷新；实时失败回退旧快照并标记 `stale=True`。
- **行情：实时优先**。实时失败才回退最多 1 天前的快照，并标记 `stale=True`。
- **新闻：仍实时**（旧新闻比没有新闻更危险），没有做快照。

## 3. TTL 与 key

| 数据 | kind | key | 快照优先 | 新鲜期 | 回退 |
|---|---|---|---|---|---|
| A 股财务 | `financials_cn` | `600519.SH` | 是 | 30 天 | 任意旧快照，标 stale |
| 港股财务 | `financials_hk` | `00700.HK` | 是 | 30 天 | 任意旧快照，标 stale |
| 美股财务 | `financials_us` | `AAPL` | 是 | 30 天 | 任意旧快照，标 stale |
| 公司概况 | `profiles` | `CN:600519.SH` | 是 | 30 天 | 任意旧快照，标 stale |
| 行情 | `quotes` | `US:AAPL` | 否 | 实时 | ≤1 天，标 stale |

目录：`backend/data/snapshots/<kind>/<key>.json`
（可用 `DATA_SNAPSHOT_DIR` 改）。

每个快照：
```json
{
  "meta": {
    "kind": "financials_hk",
    "key": "00700.HK",
    "source": "akshare_eastmoney_hk",
    "fetched_at": "2026-10-25T16:50:20+00:00",
    "period_end": "2025-12-31",
    "stale": false
  },
  "payload": { "...": "原始 dict" }
}
```

工具返回时会在 payload 里加 `_data_meta`：
```json
"_data_meta": {
  "source": "snapshot",
  "original_source": "eval_seed",
  "fetched_at": "...",
  "period_end": "2025-12-31",
  "age_days": 0.0,
  "stale": false
}
```

`normalize_financial_data` 会忽略它；报告摘要会读到它，并在附录标注
“数据来自本地快照/抓取时间”。

## 4. 怎么用

### 4.1 从最近一次评测灌快照（最快）

```powershell
cd agentic_research/backend
python scripts/seed_snapshots_from_eval.py
```

读取 `tests/eval/results/runs.jsonl` 每个 symbol 的最后一次运行，
把 `03_financial_raw.json` / `02_company_profile.json` 写成快照。
本轮已灌：30 份财务 + 30 份概况。

### 4.2 主动刷新（建议评测前/每周）

```powershell
# 30 家全量，财务+概况+行情
python scripts/prewarm_data.py --sample core

# 只刷新 3 家财务
python scripts/prewarm_data.py --symbols AAPL,600519.SH,00700.HK --only financials

# 只刷概况
python scripts/prewarm_data.py --sample core --only profiles
```

脚本默认 `DATA_FORCE_LIVE=1`，跳过新鲜快照直接打实时；
成功写快照，失败但有旧快照会打印 `stale=True`，不中断整批。

### 4.3 应用运行时

不需要改调用方：`financial_analyzer` / `info_collector` 还是调原来的工具，
工具内部自动走快照优先/回退。

### 4.4 检查快照状态

```powershell
python -c "from app.services import snapshot_store as s; import json; print(json.dumps(s.stats(), ensure_ascii=False, indent=2))"
```

## 5. 验证：把实时源全部打挂，仍能出数

已做过的验证（`unittest.mock.patch` 让 akshare/HTTP 直接抛错）：

| 数据 | 结果 |
|---|---|
| A 股财务 600519 | 从快照返回 922.78 亿营收 / 445.17 亿归母，`stale=False` |
| 港股财务 00700 | 从快照返回 7436.89 亿营收 / 2248.42 亿股东应占溢利，`stale=False` |
| 美股财务 AAPL | 从快照返回 4161.61 亿营收，`stale=False` |
| A 股概况 600519 | 从快照返回公司名，`stale=False` |

也就是说：**akshare 挂了，报告仍能跑；数据不会“今天有、明天没有”。**

另外用 3 家（AAPL / 600519 / 00700）跑了一次快照优先的端到端：

| 公司 | 字段 | financial_analyzer 耗时 | 结果 |
|---|---|---|---|
| AAPL | 5/5 | ~20ms | success |
| 600519.SH | 5/5 | ~20ms | success |
| 00700.HK | 5/5 | ~20ms | success |

财务节点从原来的 2–10 秒（实时 akshare/SEC）降到 **20ms 级**；报告仍会照常生成，
并在附录标注 `data_source=snapshot` 与抓取时间。

## 6. 取舍与注意

1. **快照不是实时**：财务/概况 30 天内可能不更新；报告附录必须写
   `data_source` / `fetched_at` / `period_end`，`stale=true` 时必须写“非实时”。
2. **行情快照只做兜底**：≤1 天，仍可能过期；不要把快照价格当实时价。
3. **新闻不快照**：避免把旧闻当新闻。
4. **刷新策略**：建议每周/每次评测前跑一次 `prewarm_data.py`；
   财报季加密到每天。
5. **不要手工改快照 JSON**：用 `prewarm_data.py` 或 `seed_snapshots_from_eval.py`。
6. **快照体积**：每份财务 JSON 几 KB～几十 KB，30 家约 1–2 MB，可入 git（或 gitignore 后由 CI 预热）。

## 7. 与评测的关系

- 评测工装的 `instrument` 会记录 `stale`；
  指标 7 的备注会显示“快照回退 N 次”。
- 评测报告必须区分“实时成功”和“快照回退成功”，不能把 stale 当实时。
- `results/runs/<run_id>/result.json` 里的 `tool_calls[].stale` 可审计。
- 全量 30 家复测：财务 149/150，工具 338/348；快照层上线后不会再因 akshare 抖动丢样本。
